# TESTER_PLAN_P1_00: Verify Spirit of the Project

## Phase 1 Goal

Verify that the motionbert-pose pipeline respects the academic spirit of the capstone project, specifically:

1. Real Stacked Hourglass heatmaps (not synthetic Gaussians) are used in the FK optimization scoring.
2. Other constraints from the capstone report are respected.

## Tests

### Test 1: Smoke Test -- `test_single.py` runs to completion

**What:** Run `test_single.py` on the first CMU Panoptic example. Verify it completes without errors and produces reasonable output.

**How:** `cd motionbert-pose && uv run python test_single.py`

**Pass criteria:** Exit code 0, MPJPE values printed, no tracebacks.

### Test 2: Code Review -- Real heatmaps are used in scoring (not just passed through)

**What:** Trace the heatmap data flow from `detect.py` through `optimize.py` to `scoring.py`. Verify that when `USE_REAL_HEATMAPS=True`, the optimizer actually samples from the (16, 64, 64) Stacked Hourglass heatmaps via `grid_sample`, not from synthetic Gaussians centered on keypoints.

**How:** Code review of:
- `config.py`: `USE_REAL_HEATMAPS` must be `True`
- `detect.py` -> `detect_poses()`: Must return raw heatmaps from Stacked Hourglass
- `main.py` / `test_single.py`: Must pass heatmaps + affine to `run_optimization()`
- `optimize.py` -> `run_optimization()`: Must convert heatmaps to tensors and pass to `compute_total_score()` with `use_real_heatmaps=True`
- `scoring.py` -> `compute_total_score()`: Must call `real_heatmap_score()` when `use_real_heatmaps=True`
- `scoring.py` -> `real_heatmap_score()`: Must use `F.grid_sample` on the actual heatmap tensor (not on a synthetic Gaussian)

**Pass criteria:** Complete chain from Stacked Hourglass output to `grid_sample` is verified. No synthetic Gaussian substitution when `USE_REAL_HEATMAPS=True`.

### Test 3: Code Review -- Heatmaps come from Stacked Hourglass (not generated)

**What:** Verify that the heatmaps passed to the optimizer are the raw outputs from the Stacked Hourglass neural network, not generated by placing Gaussian blobs on keypoint locations.

**How:** Trace `run_hourglass()` in `detect.py`. The heatmaps must come from `model(inp)[-1]`, not from a Gaussian generation function.

**Pass criteria:** Heatmaps are direct network output, averaged with flip augmentation, and not post-processed into synthetic Gaussians.

### Test 4: Code Review -- H36M-to-MPII heatmap mapping is correct

**What:** Verify `H36M_TO_MPII_HEATMAP` mapping in `scoring.py` correctly maps each H36M joint to its MPII heatmap channel.

**How:** Cross-reference with `mpii_to_h36m()` in `skeleton.py` and the MPII joint order.

**Pass criteria:** All 15 mapped joints are correct. Hip (0) and Spine (7) correctly fall back to analytical Gaussian.

### Test 5: Code Review -- Other capstone report constraints

**What:** Verify the pipeline respects the capstone report's core claims:
- Rigid skeleton parameterization (joint angles, not raw coordinates)
- Bone lengths shared across frames
- Forward kinematics is differentiable
- Temporal smoothness penalties are applied
- Coarse-to-fine schedule exists
- Evaluation uses MPJPE and P-MPJPE

**How:** Review `optimize.py`, `scoring.py`, `config.py`, `fk.py`.

**Pass criteria:** All listed constraints are satisfied.

### Test 6: Runtime verification -- log output confirms real heatmaps

**What:** Verify the runtime output from `test_single.py` includes the message "Using real Stacked Hourglass heatmaps for scoring" (not "analytical Gaussian").

**How:** Inspect stdout from Test 1.

**Pass criteria:** Log line confirms real heatmaps are active.
