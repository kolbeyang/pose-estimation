## Phase 2: Fix Stretched Heatmaps

**Changes in `scoring.py:generate_synthetic_heatmaps()`:**
- Replaced single `sigma_hm = sigma / sx` with per-axis: `sigma_hm_x = sigma / sx`, `sigma_hm_y = sigma / sy`
- Gaussian exponent now uses separate sigmas: `(xx-cx)^2/(2*sigma_x^2) + (yy-cy)^2/(2*sigma_y^2)`
- For square images, behavior is identical (sx == sy)
- For non-square (e.g., 1080x1920), the Gaussian is now circular in pixel space

**Verified by:** `test_non_square_circular_in_pixel_space` test confirms asymmetric heatmap values at equal heatmap distances.

## Critical Decisions

1. **Combined Phase 1+3 commit:** The skeleton function renames were required for the import changes in Phase 1 to work. Splitting them would have required temporary compatibility shims (violates "no backward compat" rule).

2. **FK chain preserved:** The 16-joint skeleton structure and PARENTS array are unchanged. Joint 7 (Spine) remains as an FK-internal joint -- it has no detection signal in MediaPipe mode but does in MotionBert mode (via MPII[7]).

3. **MotionBert now scores 16 joints instead of 14:** Since MPII[6] (Pelvis) and MPII[7] (Thorax/Spine) are now mapped, the heatmap scoring uses all 16 channels. This should improve optimization convergence.
