# Plan: Full Pipeline Comparison -- MediaPipe vs MotionBert

## Overview

Run both pipelines on all 25 examples, then build a comparison script that produces comprehensive graphs answering "Which is better, MotionBert or MediaPipe?"

There are three phases: validate configs, run both pipelines, build comparison graphs.

## Discussion

### Current State

- Both `run_full_config.json` files (mediapipe and motionbert) have **identical** 25 examples. These were already curated in commit `1022b39` to replace broken examples (out-of-range frames, missing GT, multi-person sequences).
- **A previous successful full run already exists** with 25/25 results.json files in both:
  - `output/mediapipe_2026_03_29_21_33/` (25 results)
  - `output/motionbert_2026_03_29_21_24/` (25 results)
- A basic `output/comparison/` directory exists from a previous `compare.py` (now deleted) with `aggregate_metrics.json` and `per_video_metrics.json` containing all 25 examples.
- `graphs.py` has per-example graphing but no cross-pipeline comparison functionality.

### Key Design Decisions

1. **Re-run vs reuse existing data.** The existing runs from 03_29 have all 25 examples with valid results. However, the spec from `2026-03-30.md` introduced skeleton changes (14 eval joints instead of 12, joint renaming). We should **re-run both pipelines** to ensure results reflect the latest code. This also ensures reproducibility.

2. **Comparison script design.** Build a single `compare.py` that:
   - Takes two output directories as arguments (one mediapipe, one motionbert)
   - Loads all `results.json` files from each
   - Produces all comparison graphs into a `comparison/` output directory
   - No persistent state, no database -- just reads JSON and produces PNGs + a summary JSON

3. **What graphs answer "which is better?"**
   - **Per-example side-by-side bar chart** (the core graph): each example on X, VW-SI-MPJPE for MediaPipe vs MotionBert on Y
   - **Aggregate metrics table** (printed + saved as JSON): mean, median, std across all 25 examples for all 9 metrics
   - **Win/loss count**: how many examples does each pipeline win?
   - **Box plots**: distribution of per-example errors for each pipeline
   - **Per-joint comparison**: which joints does each pipeline handle better?
   - **Velocity comparison**: which pipeline produces smoother motion?
   - **Scatter plot**: MediaPipe error vs MotionBert error per example (points above diagonal = MotionBert wins)

### What "better" means

The primary metric is **VW-SI-MPJPE** (visibility-weighted, scale-independent MPJPE) -- this is the project's designated primary evaluation metric per `evaluate.py:242`. Secondary metrics: SI-MPJPE (without visibility weighting), MPJVE/VW-SI-MPJVE (smoothness).

### Config file vs cmu_data.EXAMPLES discrepancy

The `run_full_config.json` files have 25 examples that **differ** from `cmu_data.EXAMPLES`. The configs were curated after discovering broken examples. The configs are the source of truth -- `cmu_data.EXAMPLES` is stale and should be updated to match, but that is out of scope for this task.

## Phase 3: Build Comparison Script and Generate Graphs

### Title
Create `compare.py` with comprehensive comparison graphs

### Implementation

Create `pose-optimizer/compare.py` that takes two output directories and produces a comparison.

**Usage:**
```bash
cd pose-optimizer
uv run python compare.py output/mediapipe_TIMESTAMP output/motionbert_TIMESTAMP
```

**What it does:**

1. **Load data:** Walk both directories, load every `results.json`, match examples by name (the subdirectory name like `171204_pose1_1000`). Skip any example that doesn't exist in both directories.

2. **Generate the following graphs** into `output/comparison_<timestamp>/`:

   **Graph 1: Per-Example VW-SI-MPJPE Bar Chart** (`per_example_vw_si_mpjpe.png`)
   - Grouped bar chart, 25 examples on X-axis
   - Two bars per example: MediaPipe (blue) and MotionBert (orange)
   - Y-axis in cm
   - Sort examples by MediaPipe error (ascending) for readability
   - This is THE primary comparison graph

   **Graph 2: Per-Example SI-MPJPE Bar Chart** (`per_example_si_mpjpe.png`)
   - Same as above but for SI-MPJPE (without visibility weighting)

   **Graph 3: Aggregate Metrics Bar Chart** (`aggregate_metrics.png`)
   - Mean across all 25 examples for each of the 9 metrics
   - Two bars per metric: MediaPipe vs MotionBert
   - Show both raw (detector) and optimized values

   **Graph 4: Box Plot of Per-Example Errors** (`error_distribution.png`)
   - 4 box plots side by side: MP-Raw, MP-Opt, MB-Raw, MB-Opt
   - Shows spread/outliers of VW-SI-MPJPE across 25 examples

   **Graph 5: Scatter Plot** (`scatter_mpjpe.png`)
   - X = MediaPipe VW-SI-MPJPE, Y = MotionBert VW-SI-MPJPE, one dot per example
   - Diagonal line (y=x) -- points below = MediaPipe wins, above = MotionBert wins
   - Annotate with example names

   **Graph 6: Per-Joint Error Comparison** (`per_joint_comparison.png`)
   - Mean per-joint MPJPE across all 25 examples, for each of the 14 eval joints
   - Grouped bar: MediaPipe vs MotionBert

   **Graph 7: Velocity Error Comparison** (`velocity_comparison.png`)
   - Per-example MPJVE bar chart (same format as Graph 1 but for velocity)

   **Graph 8: Win/Loss Summary** (`win_loss.png`)
   - Simple pie chart or bar: N examples where MediaPipe wins vs MotionBert wins (by VW-SI-MPJPE)

3. **Save summary data** as `output/comparison_<timestamp>/summary.json`:
   ```json
   {
     "mediapipe_dir": "...",
     "motionbert_dir": "...",
     "num_examples": 25,
     "mediapipe_mean_vw_si_mpjpe": 0.12,
     "motionbert_mean_vw_si_mpjpe": 0.14,
     "mediapipe_wins": 15,
     "motionbert_wins": 10,
     "per_example": { ... },
     "aggregate": { ... }
   }
   ```

4. **Print a text summary** to stdout:
   ```
   === Pipeline Comparison: MediaPipe vs MotionBert ===
   Examples compared: 25

   Primary Metric (VW-SI-MPJPE, cm):
     MediaPipe:  mean=12.0  median=11.5  std=3.2
     MotionBert: mean=14.0  median=12.0  std=5.1

   Winner by VW-SI-MPJPE: MediaPipe wins 15/25, MotionBert wins 10/25

   Graphs saved to: output/comparison_<timestamp>/
   ```

**Key implementation details:**
- Use matplotlib with Agg backend (no display needed)
- Load `results.json` -> `metrics` dict has optimized metrics, `raw_metrics` has detector metrics
- Per-joint data is in `per_joint.opt_per_joint` (list of 14 floats for eval joints)
- Joint names come from `skeleton.py:EVAL_JOINT_NAMES`
- All metric values are in meters -- multiply by 100 for cm display
