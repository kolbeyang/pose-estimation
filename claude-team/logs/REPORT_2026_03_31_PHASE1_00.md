## Format Tag Vocabulary Used

All tags are from the approved vocabulary:

- `[2D:MEDIAPIPE_33]`, `[3D:MEDIAPIPE_33]`, `[VIS:MEDIAPIPE_33]`
- `[2D:MPII_16]`, `[2D:MPII_17]`
- `[3D:MOTIONBERT_17]`
- `[HEATMAP:MPII_16]`
- `[2D:SKELETON_16]`, `[3D:SKELETON_16]`, `[VIS:SKELETON_16]`
- `[HEATMAP:SKELETON_16]`
- `[3D:COCO19]`
- `[3D:SKELETON_16_EVAL]`
- `[FK_PARAMS]`
- `[SKELETON_16]` (for constant/config indexing context)

## Critical Decisions

1. **`[*:SKELETON_16]` wildcard in `strip_head_joint`**: Used `[*:SKELETON_16]` notation because the function is generic over 2D/3D dimensionality. This is consistent with how the plan describes it.

2. **`[HEATMAP-derived]` note in `mpii_to_skeleton`**: Added a brief note that input can also be heatmap-derived keypoints (with confidence column), since that's the actual usage pattern.

3. **Private function docstrings**: Added docstrings to all private functions (`_normalize_for_sh`, `_flip_heatmaps`, `_parse_heatmaps`, `_iqr_filtered_median`, etc.) as specified in the plan. Pure math helpers in `fk.py` (`_axis_angle_to_matrix`, `_rotation_between_vectors`, `_rotation_matrix_to_axis_angle`) already had adequate docstrings and were left with minimal changes per plan guidance.

4. **Inline tag placement**: Placed inline `# [DIM:JOINTS]` comments on variable declaration lines (after the `=` or `)`) rather than on separate comment lines, matching the convention in the plan.

5. **Tuple unpacking tags**: For multi-return unpacking (e.g., `detect_poses()` return), placed tags as end-of-line comments on each variable in the destructuring.
