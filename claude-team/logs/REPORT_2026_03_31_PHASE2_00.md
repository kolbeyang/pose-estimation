## Summary

Replaced the heuristic depth estimation in `motionbert_to_camera_space` with `cv2.solvePnPRansac`, unifying the MotionBERT pipeline with the MediaPipe pipeline's approach to 3D-to-camera-space conversion.

## Changes

### `pose-optimizer/run_motionbert/detect.py`

1. **New function `_depth_heuristic_fallback`** (lines 540-587): Extracted the old pairwise Y-axis depth heuristic into a standalone fallback function. Called when solvePnP fails or fewer than 4 valid 2D points exist.

2. **Rewritten `motionbert_to_camera_space`** (lines 590-671):
   - **Step 1 unchanged:** Bone-length-based scale estimation using `DEFAULT_BONE_LENGTHS` ratios with IQR-filtered median.
   - **Step 2 replaced:** Old pairwise depth heuristic replaced with `cv2.solvePnPRansac(reprojectionError=8.0)`. Finds the full rigid transform (R, t) from bone-scaled 3D points to camera space.
   - Depth clipped to [1.0, 8.0] meters as safety.
   - Falls back to `_depth_heuristic_fallback` if solvePnP fails or insufficient valid points.

3. **No changes to function signature.** Input/output contract identical.

### Observations

- **VW-SI-MPJPE** degradation is small on average (+3.8%), though pose1 individually is +18%.
- **MPJVE** (velocity error) is notably higher with solvePnP, particularly for pose1 (+453%). This is because solvePnPRansac finds a slightly different rotation per frame (~18 deg mean, ~6 deg std), introducing frame-to-frame jitter. The old heuristic assumed identity rotation, which was smoother.
- **SI-MPJPE** and **P-MPJPE** are similar between approaches (scale/rotation-invariant metrics are unaffected).
- The optimizer still helps in all cases (Opt < Det for VW-SI-MPJPE).

## Iteration History

1. **Initial attempt: `cv2.solvePnP` with `SOLVEPNP_SQPNP`** -- Severe degradation. SQPNP found depths < 1.0m (clipped) vs GT ~2.6m. VW-SI-MPJPE +54% on pose1. Root cause: outlier 2D-3D correspondences (17px mean reprojection error) caused the non-robust solver to produce bad fits.

2. **Fix: Switched to `cv2.solvePnPRansac(reprojectionError=8.0)`** -- Dramatically improved depth estimation. RANSAC depths (mean 2.28m, std 0.12m) closely match both the heuristic (2.28m) and GT (2.62m). SQPNP depths were mean 1.66m, std 0.63m.

3. **Remaining issue: rotation noise** -- solvePnPRansac rotation varies ~6 degrees frame-to-frame, causing MPJVE degradation. MotionBERT's coordinate system is roughly camera-aligned (mean rotation ~18 degrees from identity) but with per-frame noise. This is inherent to the solvePnP approach.

## Design Decisions

- **RANSAC over SQPNP:** MotionBERT's 3D predictions have enough outlier joints that a robust solver is essential. SQPNP was unusable.
- **Full R+t applied (not translation-only):** Matches the MediaPipe pattern exactly. The rotation correction is physically meaningful (~18 degrees) even though frame-to-frame variation adds noise.
- **Depth clip retained:** [1.0, 8.0] meter safety clip, same as original heuristic.
- **Fallback preserved:** The old heuristic is preserved as `_depth_heuristic_fallback` for edge cases.
