# Phase 2 Plan: Unify MotionBERT Depth Estimation with solvePnP

**Date:** 2026-03-31
**Scope:** Replace heuristic scale+depth estimation in `motionbert_to_camera_space` with `cv2.solvePnP`, matching MediaPipe's approach.

---

## Overview

Currently, `motionbert_to_camera_space` (in `pose-optimizer/run_motionbert/detect.py:540`) uses a two-step heuristic approach:
1. **Scale estimation**: Compare detected bone lengths against `DEFAULT_BONE_LENGTHS` to compute a `bone_scale` factor
2. **Depth estimation**: Estimate root depth `tz` from pairwise Y-axis correspondences between 3D and 2D joints

MediaPipe's `mediapipe_3d_to_camera` (in `pose-optimizer/run_mediapipe/detect.py:111`) uses `cv2.solvePnP` to solve for the full rigid transform (R, t) from 3D-to-2D correspondences in a single step. This is cleaner: solvePnP jointly estimates scale, rotation, and translation.

The goal is to unify the approaches so both pipelines use solvePnP for the 3D-to-camera-space conversion.

---

## Discussion

### How the current MotionBERT heuristic works

**File:** `pose-optimizer/run_motionbert/detect.py:540-612`

The function `motionbert_to_camera_space` takes:
- `positions_3d_norm`: (16, 3) MotionBERT-normalized positions (arbitrary scale, hip-relative offsets baked in)
- `kp_2d`: (16, 2) pixel coordinates from Stacked Hourglass
- `fx, fy, cx, cy`: camera intrinsics

**Step 1 -- Scale estimation (lines 560-580):**
```python
root_relative = positions_3d_norm - positions_3d_norm[0:1]
```
For each bone, it computes the ratio `DEFAULT_BONE_LENGTHS[j] / detected_bone_length`. It uses IQR-filtered median of these ratios as `bone_scale`. Only "reliable" bones (indices 10-15: shoulders, elbows, wrists) are preferred. The result `root_relative_m = root_relative * bone_scale` is in approximate meters.

**Step 2 -- Depth estimation (lines 582-612):**
For all joint pairs (i, j), it computes `tz = fy * dy_3d / dv_2d` where `dy_3d` is the 3D Y-distance and `dv_2d` is the 2D pixel Y-distance. IQR-filtered median of these candidates gives the root depth `tz`, clipped to [1.0, 8.0] meters. Root XY is back-projected from the 2D hip position using `tz`.

**Key observations:**
- Scale and depth are estimated separately, introducing potential inconsistency
- Only Y-axis is used for depth (ignores X-axis information)
- No rotation correction -- assumes MotionBERT output is already camera-aligned
- `_RELIABLE_BONES_FOR_SCALE = {10, 11, 12, 13, 14, 15}` (upper body only)
- Helper `_iqr_filtered_median` provides outlier-robust aggregation

### How MediaPipe's solvePnP approach works

**File:** `pose-optimizer/run_mediapipe/detect.py:111-149`

The function `mediapipe_3d_to_camera` takes:
- `mp_3d`: (16, 3) hip-relative world coords (already in meters -- MediaPipe provides this)
- `mp_2d`: (16, 2) pixel coordinates
- `fx, fy, cx, cy`: camera intrinsics

**Implementation:**
```python
K = np.array([[fx, 0, cx], [0, fy, cy], [0, 0, 1]], dtype=np.float64)
dist_coeffs = np.zeros(4, dtype=np.float64)

valid = np.linalg.norm(mp_2d, axis=1) > 1.0  # filter zero/missing joints
obj_pts = mp_3d[valid].astype(np.float64)
img_pts = mp_2d[valid].astype(np.float64)

success, rvec, tvec = cv2.solvePnP(
    obj_pts, img_pts, K, dist_coeffs, flags=cv2.SOLVEPNP_SQPNP,
)

R, _ = cv2.Rodrigues(rvec)
cam_3d = (R @ mp_3d.T).T + tvec.T
```

**Key observations:**
- MediaPipe's 3D output is already in real-world units (meters), so solvePnP only needs to find the rigid transform (R, t) to place the skeleton in camera space
- Uses `SOLVEPNP_SQPNP` flag (robust, works with any number of points >= 4)
- Falls back to `_depth_heuristic_fallback` if fewer than 4 valid points or solvePnP fails
- Zero distortion coefficients (Panoptic data is already undistorted, or distortion is negligible)

### The key difference: MotionBERT output is NOT in real-world units

MotionBERT outputs positions in an arbitrary normalized scale. The current heuristic uses bone length ratios to recover the real-world scale before estimating depth. For solvePnP to work, the 3D object points must be in consistent real-world units.

**Solution:** Keep the bone-length-based scale estimation (Step 1), then use solvePnP instead of the pairwise depth heuristic (Step 2). The scaled root-relative positions become the "object points" for solvePnP, just like MediaPipe's world coordinates.

### Camera model

**File:** `pose-optimizer/camera.py`

Standard pinhole model:
- `fx, fy`: focal lengths in pixels
- `cx, cy`: principal point
- Projection: `u = fx * X / Z + cx`, `v = fy * Y / Z + cy`
- Extrinsics (R, t) transform world -> camera space

The intrinsics are extracted from the Panoptic calibration's K matrix (`cam_calib["K"]`). These are passed directly to `motionbert_to_camera_space` as `fx, fy, cx, cy`.

### Bone length reference data

**File:** `pose-optimizer/skeleton.py:61-78`

`DEFAULT_BONE_LENGTHS` in meters (typical 1.7m adult):
```
0: 0.00 (root)      7: 0.22 (Pelvis->Spine)
1: 0.12 (Pelvis->RHip)   8: 0.22 (Spine->Neck)
2: 0.42 (RHip->RKnee)    9: 0.12 (Neck->Head)
3: 0.40 (RKnee->RAnkle) 10: 0.18 (Neck->LShoulder)
4: 0.12 (Pelvis->LHip)  11: 0.28 (LShoulder->LElbow)
5: 0.42 (LHip->LKnee)   12: 0.25 (LElbow->LWrist)
6: 0.40 (LKnee->LAnkle) 13: 0.18 (Neck->RShoulder)
                         14: 0.28 (RShoulder->RElbow)
                         15: 0.25 (RElbow->RWrist)
```

Total skeleton height (pelvis to ankle): ~0.94m. Full standing height (head to ankle): ~1.40m.

### Sub-phase 2: Implementation

**Goal:** Replace the depth heuristic in `motionbert_to_camera_space` with `cv2.solvePnP`.

**File to modify:** `pose-optimizer/run_motionbert/detect.py`

**Changes:**

1. **Add `import cv2` at the top of the file** (if not already present).

2. **Rewrite `motionbert_to_camera_space`** to:

   a. **Keep the bone-scale estimation (lines 558-580 unchanged).** MotionBERT output is not in real-world units, so we still need to recover meters from bone length ratios. This produces `root_relative_m`.

   b. **Replace the depth heuristic (lines 582-612) with solvePnP:**

   ```python
   # Build camera matrix
   K = np.array([
       [fx, 0, cx],
       [0, fy, cy],
       [0, 0, 1],
   ], dtype=np.float64)
   dist_coeffs = np.zeros(4, dtype=np.float64)

   # Filter valid 2D detections
   valid = np.linalg.norm(kp_2d, axis=1) > 1.0
   if valid.sum() < 4:
       # Fallback to the old heuristic depth estimation
       return _depth_heuristic_fallback(root_relative_m, kp_2d, fx, fy, cx, cy)

   obj_pts = root_relative_m[valid].astype(np.float64)
   img_pts = kp_2d[valid].astype(np.float64)

   success, rvec, tvec = cv2.solvePnP(
       obj_pts, img_pts, K, dist_coeffs, flags=cv2.SOLVEPNP_SQPNP,
   )

   if not success:
       return _depth_heuristic_fallback(root_relative_m, kp_2d, fx, fy, cx, cy)

   R, _ = cv2.Rodrigues(rvec)
   cam_3d = (R @ root_relative_m.T).T + tvec.T
   return cam_3d.astype(np.float64)
   ```

   c. **Extract the old depth heuristic into a fallback function** `_depth_heuristic_fallback(root_relative_m, kp_2d, fx, fy, cx, cy)` that implements the current lines 582-612 logic. This serves as the fallback when solvePnP fails or insufficient valid 2D points exist.

3. **Key design decisions:**

   - **solvePnP flag:** Use `cv2.SOLVEPNP_SQPNP` to match MediaPipe. This is a robust solver that works well with >= 4 points. Alternative: `SOLVEPNP_ITERATIVE` (the default) or `SOLVEPNP_EPNP`.

   - **Rotation from solvePnP:** Unlike the current heuristic which assumes no rotation correction is needed, solvePnP will find an R matrix. MotionBERT's output is roughly camera-aligned but not exactly. The R from solvePnP should be close to identity -- if it is very far from identity, that could indicate a problem.

   - **Depth clipping:** The current heuristic clips `tz` to [1.0, 8.0]. Consider whether to clip `tvec[2]` similarly as a safety measure. Recommended: yes, clip to same range.

   - **No changes to the function signature.** The function still takes the same inputs and returns (16, 3) camera-space meters.

4. **Remove dead code:** After the rewrite, `_iqr_filtered_median` and `_RELIABLE_BONES_FOR_SCALE` are still needed for bone scale estimation. The old depth heuristic code moves into the fallback function.

### Sub-phase 3: Verification

**Goal:** Confirm the solvePnP approach produces comparable or better MPJPE.

**Steps:**

1. Re-run the same 3-5 benchmark examples used in Sub-phase 1.

2. Compare detector-only metrics (MPJPE, SI-MPJPE, VW-SI-MPJPE, P-MPJPE) before vs. after.

3. **Acceptance thresholds:**
   - VW-SI-MPJPE change within +/-5% is acceptable
   - SI-MPJPE should be very similar (scale-independent, unaffected by depth changes)
   - P-MPJPE should be nearly identical (Procrustes removes scale/rotation/translation)

4. **Diagnostic checks:**
   - Print the solvePnP rotation matrix for a few frames -- it should be close to identity (MotionBERT output is roughly camera-aligned)
   - Print `tvec[2]` (depth) and compare to the old heuristic's `tz` values
   - If R is far from identity, that is informative but not necessarily wrong -- it means MotionBERT's coordinate frame differs from camera frame

5. Also run the full pipeline (with optimizer) on those examples to confirm the optimizer still helps.

### Sub-phase 4: Iteration

**If performance degrades, here is the debugging/tuning playbook:**

1. **Check if solvePnP rotation is unstable:**
   - Print the Rodrigues angle magnitude `np.linalg.norm(rvec)` per frame. If it varies wildly (e.g., > 0.5 rad), the solver may be poorly conditioned.
   - **Fix:** Try `SOLVEPNP_EPNP` or `SOLVEPNP_ITERATIVE` instead of `SOLVEPNP_SQPNP`.

2. **Check if bone_scale is the bottleneck:**
   - If solvePnP produces good relative poses but wrong absolute scale, the bone_scale estimation may be off.
   - **Fix:** Tune `_RELIABLE_BONES_FOR_SCALE` -- try including leg bones (indices 2, 3, 5, 6) which are long and stable. Or try using all bones.

3. **Check if certain joints are hurting solvePnP:**
   - Noisy 2D detections (especially ankles, which the final report notes are problematic) can pull solvePnP off.
   - **Fix:** Filter by confidence/visibility before passing to solvePnP. Only use joints with high Stacked Hourglass confidence (the `visibility` output from `detect_poses`). E.g., `valid = (np.linalg.norm(kp_2d, axis=1) > 1.0) & (visibility > 0.5)`.

4. **Try RANSAC-based solvePnP:**
   - `cv2.solvePnPRansac` is more robust to outlier correspondences.
   - **Fix:** Replace `cv2.solvePnP` with `cv2.solvePnPRansac(obj_pts, img_pts, K, dist_coeffs, reprojectionError=8.0)`.

5. **Slight tuning of DEFAULT_BONE_LENGTHS:**
   - If the person in the test sequences is significantly different from the 1.7m default, bone_scale will be biased.
   - **Fix:** Adjust bone lengths by up to ~10%. Check the GT bone lengths from `results.json` -> `gt_bone_lengths` to calibrate.

6. **MotionBERT Y-axis flip:**
   - MotionBERT may use a different Y-axis convention than the camera frame. If solvePnP finds a large rotation, try flipping `root_relative_m[:, 1] *= -1` before solvePnP.

7. **Stacked Hourglass / YOLO configuration:** Only relevant if 2D keypoints are the bottleneck. Not expected to need changes.

### Sub-phase 5: Testing / Definition of Done

**Concrete acceptance criteria:**

1. **Functional:**
   - `motionbert_to_camera_space` uses `cv2.solvePnP` as primary depth/transform estimation
   - Heuristic fallback exists and is triggered when solvePnP fails or < 4 valid points
   - Function signature unchanged: `(positions_3d_norm, kp_2d, fx, fy, cx, cy) -> (16, 3)`

2. **Performance (detector-only, no optimizer):**
   - VW-SI-MPJPE within 5% of baseline on the benchmark examples
   - No example regresses by more than 20% on any metric
   - solvePnP succeeds (does not fall back to heuristic) on >= 90% of frames

3. **Performance (with optimizer):**
   - Optimizer still improves VW-SI-MPJPE over detector on the benchmark examples
   - Optimizer improvement percentage is within 3% of baseline improvement percentage

4. **Code quality:**
   - Implementation mirrors the MediaPipe pattern in `mediapipe_3d_to_camera`
   - Fallback function is clean and well-documented
   - No dead code left behind

5. **Verification artifact:**
   - A comparison table (baseline vs solvePnP) printed to stdout or saved to file, covering the benchmark examples with all key metrics
