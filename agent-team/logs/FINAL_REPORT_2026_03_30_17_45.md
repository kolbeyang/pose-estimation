**`MOTIONBERT_SKELETON` (16 joints):**
```
Pelvis(0) -> Thorax(14) -> BaseOfNeck(7) -> RShoulder(8)/LShoulder(11)/HeadTop(15)
Pelvis(0) -> RHip(1)/LHip(4)
```
- 14 eval joints (indices 0-13), 2 opt-only (Thorax=14, HeadTop=15)

**`MEDIAPIPE_SKELETON` (15 joints):**
```
Pelvis(0) -> BaseOfNeck(7) -> RShoulder(8)/LShoulder(11)/Nose(14)
Pelvis(0) -> RHip(1)/LHip(4)
```
- 14 eval joints (indices 0-13), 1 opt-only (Nose=14)

Joint mapping functions:
- `mpii_to_motionbert_skeleton()` -- direct index mappings, no midpoints
- `mediapipe_to_skeleton()` -- exactly 2 midpoints: Pelvis=mid(LHip,RHip), BaseOfNeck=mid(LShoulder,RShoulder)
- `coco19_to_motionbert_skeleton()` / `coco19_to_mediapipe_skeleton()` -- GT mappings
- All verified against the spec's MPII/MediaPipe/COCO19 index tables

Key architectural change: FK functions now accept `SkeletonConfig` parameters instead of using globals. Topological ordering handles non-sequential parent indices (e.g., BaseOfNeck=7 has parent Thorax=14 in MotionBert mode).

### 3. Stretched Heatmap Fix (Phase 3)

`scoring.py:generate_synthetic_heatmaps()` now uses separate X/Y sigma:
```python
sigma_hm_x = sigma / sx   # sigma_hm_y = sigma / sy
sq_dist = ((xx - cx_hm) / sigma_hm_x)**2 + ((yy - cy_hm) / sigma_hm_y)**2
```
This produces circular Gaussians in pixel space for non-square images (1920x1080).

## Critical Decisions

### 1. Python Code Out of Hyphenated Directories
Since `run-mediapipe/` and `run-motionbert/` can't be Python packages (hyphens in names), all Python modules moved to the project root. This is a significant structural change but actually simplifies the codebase by eliminating subpackage imports entirely.

### 2. Non-Sequential Parent Indices
In the MotionBert skeleton, `BaseOfNeck(7)` has parent `Thorax(14)` -- a higher index than itself. The FK code uses BFS topological ordering instead of sequential iteration to handle this correctly. See `fk.py:_topological_order()`.

### 3. H36M-16 to New Skeleton Remapping
`detect_motionbert.py` includes `_h36m16_to_skeleton()` to remap MotionBERT's output (old H36M-16 layout) to the new skeleton layout. This is a translation layer at the detection boundary.

### 4. Backward Compatibility Globals
`skeleton.py` exports backward-compat globals (`NUM_JOINTS`, `JOINT_NAMES`, `PARENTS`, etc.) defaulting to MotionBert skeleton values. These exist so code that hasn't been updated yet doesn't break, but they're a latent footgun if someone assumes they work for MediaPipe mode.
