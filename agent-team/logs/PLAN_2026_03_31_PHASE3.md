# Phase 3: Model Loading Optimization

## Overview

Both the MotionBERT and MediaPipe pipelines reload their ML models from disk on every example. When processing the full CMU Panoptic dataset (dozens or hundreds of examples), this means YOLO, Stacked Hourglass, and MotionBERT weights are deserialized and moved to GPU once per example -- a waste of tens of seconds each time. The fix is to load each model once at pipeline startup and pass it through to the per-example detection functions.

## Discussion

### Current model loading flow

**MotionBERT pipeline** (`run_motionbert/`):

1. `run_motionbert.py` calls `run_pipeline(config)` in `run_motionbert/__init__.py` (line 396).
2. `run_pipeline` loops over `config.examples` and calls `process_example(...)` per example (line 421).
3. `process_example` calls `detect_poses(frames_rgb, ...)` from `run_motionbert/detect.py` (line 176).
4. Inside `detect_poses` (line 678):
   - Calls `detect_person_bbox(frames_rgb)` which instantiates `YOLO("yolov8n.pt")` on **every call** (line 84).
   - Calls `run_hourglass(...)` which calls `hg8(pretrained=True)` and `.to(device)` on **every call** (lines 236-248).
   - Calls `run_motionbert(...)` which calls `load_motionbert_model()` and `.to(device)` on **every call** (lines 451-453).

All three models are loaded from disk, weights deserialized, and moved to GPU per example. This is the primary bottleneck.

**MediaPipe pipeline** (`run_mediapipe/`):

1. `run_mediapipe.py` calls `run_pipeline(config)` in `run_mediapipe/__init__.py` (line 401).
2. `run_pipeline` loops over examples, calls `process_example(...)` per example (line 425).
3. `process_example` calls `detect_poses(frames_rgb)` from `run_mediapipe/detect.py` (line 171).
4. Inside `detect_poses` (line 40): creates a `PoseLandmarker` via `vision.PoseLandmarker.create_from_options(options)` on **every call** (line 72). The `with` block creates and destroys the model each time.

MediaPipe model loading is lighter than torch models, but still unnecessary to repeat.

### Proposed architecture

The standard ML pattern: load models once at the top of the pipeline, pass them as arguments to functions that need them. No singletons, no global state, no module-level caching. Just explicit dependency injection.

For the MotionBERT pipeline, introduce a `MotionBertModels` dataclass that holds all three pre-loaded models. For MediaPipe, the landmarker object itself is the only model. Each pipeline's `run_pipeline` creates the models once and passes them to `process_example`, which passes them to `detect_poses`.

2. **Add a `load_all_models()` factory function** that loads all three models once:

```python
def load_all_models() -> MotionBertModels:
    """Load YOLO, Stacked Hourglass, and MotionBERT models once."""
    from ultralytics import YOLO

    device = _get_device()

    # YOLO
    yolo = YOLO("yolov8n.pt")

    # Stacked Hourglass
    from stacked_hourglass import hg8
    try:
        hourglass = hg8(pretrained=True)
    except RuntimeError:
        hourglass = hg8(pretrained=False)
        cached_path = os.path.join(torch.hub.get_dir(), "checkpoints", "bearpaw_hg8-90e5d470.pth")
        if os.path.exists(cached_path):
            state_dict = torch.load(cached_path, map_location="cpu", weights_only=False)
            hourglass.load_state_dict(state_dict)
        else:
            raise RuntimeError("Stacked Hourglass weights not found.")
    hourglass = hourglass.to(device)
    hourglass.eval()

    # MotionBERT
    motionbert = load_motionbert_model()
    motionbert = motionbert.to(device)

    print(f"  All models loaded on {device}")
    return MotionBertModels(yolo=yolo, hourglass=hourglass, motionbert=motionbert, device=device)
```

### Testing

1. **Timing comparison**: Run both pipelines with 3+ examples and compare wall-clock time before and after. Model loading for MotionBERT takes ~5-10s per model, so with 3 models x N examples, savings should be `(N-1) * ~15-30s` for MotionBERT and `(N-1) * ~2-3s` for MediaPipe.

2. **Logging verification**: The `print("  Loaded ...")` statements in `load_all_models()` and `load_landmarker()` should appear exactly once at the start of the run, not repeated per example. Grep the output log for "Loaded" and confirm count = 1 per model.

3. **Correctness**: Results (MPJPE metrics) for each example must be identical before and after the refactor. Run both pipelines on the same config and diff the `results.json` files.

4. **Single-example backward compatibility**: Verify that `detect_poses` in MediaPipe still works when called without the optional `landmarker` parameter (for any ad-hoc scripts that call it directly).
